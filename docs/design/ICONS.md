# APW-116 — Tray icon and battery glyphs

## Direction

A compact, monochrome line instrument: one open case silhouette with two short, distinct bud marks. At 16 px it reads as a case first and AirPods state second; it is not an Apple silhouette. Stroke is optically weighted for tiny raster sizes, with no text, tiny numerals or dependent color coding. The variant is identified by a simple, legible state mark.

Use a single foreground color per theme: dark ink on light taskbars, pale ink on dark taskbars. Resolve the foreground against the Windows taskbar/system theme at runtime. Use the system accent only for a charging bolt, which remains recognizable by shape. Geometry, not hue, distinguishes all other states.

## Asset contract

- Master SVGs: `icons/{state}-{light|dark}.svg`; each uses a 32×32 viewBox, no embedded raster, no external fonts, no Apple mark, and is suitable for Windows vector-to-bitmap rasterization.
- PNGs: `icons/{state}-{light|dark}-{16|20|24|32}.png`, exact square pixel dimensions, transparent background, sRGB RGBA. These are pre-rasterized delivery assets; prefer the size matching the actual taskbar scale rather than enlarging a smaller bitmap.
- States: `full`, `low`, `charging`, `unknown`, `disconnected`. All states have both themes and all four sizes (40 PNGs total).
- The tray icon is a silhouette/state glyph, not a battery percentage. Detailed L/R/case percentages belong in the tooltip, as “L 80% · R 70% · Case 60%”; unknown is “—”.

## State map

| DeviceState / condition | Asset | 16 px reading |
|---|---|---|
| Fresh known values; none at/below warning threshold | `full` | Open case + two buds |
| Any known component at ≤10% | `low` | Same case + one outlined warning diamond |
| Any component charging | `charging` | Same case + distinct bolt at upper right |
| Values missing, stale (>60 s), or model unknown without usable values | `unknown` | Same case + centered question mark in a small outlined circle |
| Confirmed disconnected endpoint | `disconnected` | Same case + diagonal slash; no state inferred from BLE silence alone |

Precedence is deterministic: **disconnected > unknown > low > charging > full**. Disconnected is endpoint-confirmed. Unknown takes precedence when stale or the readings required to determine the status are unavailable. Low takes precedence over charging if any fresh known component is ≤10%; the low mark remains visible. Do not animate or flash the tray icon.

## Visual and raster rules

- 32×32 viewBox; case body occupies x=4…28, y=11…27. Lid is open, separated by a small clear gap. Two bud stems sit above the case. State markers remain inside x=24…31, y=3…12 and must not collide with the buds.
- Use round caps/joins, consistent outline, no gradients, shadows, fills behind the glyph, or pixel-sized text. The interior is transparent.
- Ink: light-taskbar variant `#20201E`; dark-taskbar variant `#F3F2EF`. Charging accent is the Windows accent at runtime; the previews use `#0071E3` on light and `#0A84FF` on dark, matching the popup stand-in. Ensure the accent mark retains ≥3:1 contrast; if not, fall back to theme ink.
- Thin internal detail is removed before outer silhouette detail at 16 px. The state mark is at least 1.5 physical px in 16 px assets. Center optically, not just mathematically; verify each exported size at 100% display, light and dark.
- If system theme detection is unavailable, use the light asset and theme ink; never guess a colored taskbar theme from wallpaper.

## Tooltip and accessibility

Tooltip should name state and values, e.g. “AirPods Pro — Connected · L 80% · R 70% · Case 60%”. Use “Unknown” for stale values and “Disconnected” only for confirmed endpoint state. Accessible name mirrors the tooltip; never rely on glyph color alone.

## Files

Ten master SVGs and forty size-specific PNGs are kept in `icons/`. The masters are the geometry source; PNGs are raster exports. The small raster samples are generated from the masters and should be refreshed after any SVG change.

## 16 px masters

The 32 px drawings lose their bud stems when Windows scales them to 16, so a second, simplified
master exists per state in `icons/16/` (generated by `tools/make-16px.py`). It keeps three
shapes only — case, two buds, one state mark — with a 2 px stroke and no lid line. Each state
stays distinguishable at 16 px:

| State | Mark |
|---|---|
| Full | case + two buds |
| Low | dot inside the case |
| Charging | accent bolt inside the case |
| Unknown | dashed case outline |
| Disconnected | empty case, no buds |

The app picks 16 px art below 144 DPI and the 32 px master at 150 % and above.
